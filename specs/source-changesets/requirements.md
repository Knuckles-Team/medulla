| `MEDULLA-SCM-R001` | **Content-addressed blob store.** Stage: served method `SubmitChangeset`, blob phase. Each file version is a blob keyed by its content digest. Identical bytes store once. | `MEDULLA-SCM-R005.2` | **Blame.** Stage: served method `ReadBlame` and the accept of `SubmitChangeset`. The value is MessagePack `BlameEntry { state: BlameState, runs: Vec<(u32, u64)> }`. Each run is `(line_count, origin_seq)` and the runs cover the file's lines in order. `BlameState` is a `Copy` enum `Indexed`, `Binary`, `TooLarge`, `Deleted`; it classifies a row and has no transitions. Rules in `medulla_compute::source_history::apply_changeset`, per `ChangedPath` at seq `s`: `Add` gives every line origin `s`. `Modify` takes the newest blame row of the path below `s` and maps it through the line diff of `old_blob` to `new_blob`. An unchanged line keeps its origin; an inserted or replaced line takes `s`. `Rename` takes the parent vector of the `Delete` entry that immediately follows it in `changed_paths`, then applies the `Modify` rule. `Delete` writes state `Deleted` with no runs. A new blob that `is_binary` reports writes state `Binary`. A file with more than `BLAME_MAX_LINES` (2048, `Fixed`) lines on either side writes state `TooLarge`, which bounds the diff table. An index row never refuses an accept. Line diff: `split`, `diff_chunks` and `is_binary` in `crates/medulla-compute/src/line_merge.rs` become `pub(crate)` and are reused; no second diff. Blob bytes come from `AcceptContext.blobs` (`BlobIo::read`). When the newest earlier blame row of the parent path is absent, is not `Indexed`, or its runs do not cover the lines of `old_blob`, every line of the new blob takes origin `s`.
