# MEDULLA-INCREMENTAL-VIEWS — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches, its caller chain, its Shape sentence and the test that proves it as `path::name`. The generator sets each row's state in `status.json`.

Terms used in every row. A *plan view* is a plan-backed materialized view defined by `Method::PlanMatViewDefine`. A *SQL view* is a SQL materialized view of `MEDULLA-ENGINE-PARITY-R014.1`. The *kernel* is the module `crates/medulla-exec/src/incremental/`. The *manager* is `PlanMatViewManager` in `crates/medulla-server-cdc/src/matview/manager.rs`. *Incremental mode* and *recompute mode* are the two values of `Mode` in that file. A *fallback reason* is a typed code plus a text that says why a view runs in recompute mode. Every new refusal or reason code is a variant of `ServerErrorCode` in `crates/medulla-types/src/contract/server_error_code.rs`. Every knob is an environment variable read once at first use with the parse-or-default pattern of `ring_cap` in `crates/medulla-server-cdc/src/cdc.rs:44`. An out-of-range knob value falls back to the default and logs one warning. Every nightly budget fails the nightly run on a regression above 10 percent and never gates a pull request.
