| `MEDULLA-OBJECT-STORAGE-BACKEND-R001` | **Typed object-store backend specification.** Model: a `StorageBackendSpec` declares the durable-store backend for a graph. Two variants exist. `local` is redb and is the default. `object_store` is S3-compatible. The spec names endpoint, bucket and root by secret reference only. It declares a durability class. It names a layout lineage entry by digest. Behavior: the engine opens the graph from the spec. An unbound spec refuses with a named reason before any effect. An unsupported spec refuses the same way. Caller chain: `Shard::open` (`crates/medulla-store/src/redb_store/shard.rs:226`) → `admit_backend_setting` (`shard.rs:1062`, reads the `MEDULLA_STORAGE_BACKEND` setting) → `StorageBackendSpec::admit` (`crates/medulla-storage/src/backend_spec.rs:117`) → `validate` (:79). Shape: `StorageBackendSpec`, `DurabilityClass`, `SecretRef` and `BackendSpecRefusal` live in `crates/medulla-storage/src/backend_spec.rs` and are re-exported from `crates/medulla-storage/src/lib.rs`. `validate` checks the layout digest against `ALL_LAYOUTS` and `pinned_layout_digest` of the owner-store lineage registry (`crates/medulla-storage/src/owner/lineage.rs`, MEDULLA-DURABLE-KERNEL-R003). Today `admit` returns `Unsupported` for `object_store`; R002 replaces that arm with the open path, and `server_startup.rs::open_persistence` (`crates/medulla-server/src/server_startup.rs:419`) selects `ObjectStoreBackend` once `admit` passes. The store-authority binding of MEDULLA-DURABLE-KERNEL-R021 is `crates/medulla-storage/src/physical/binding.rs` and stays the only binding.
