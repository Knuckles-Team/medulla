# MEDULLA-INGEST-WORKER research

## Decisions

- **Governance refusal is per record (R900.2, R900.4, R900.5).** A record whose `_governance` member is invalid, conflicts, or lacks required retention is skipped and counted in `GovernanceReport.refused`. The rest of the batch commits. A refused record writes nothing: governance parses before the raw blob is admitted or the node is built. `affected_count` counts admitted records. `governed` includes refused records because they carry the member.
- **Retention policy is one engine knob (R900.2).** `ingest.retention_required` is a scalar Tunable knob. The knob table has no list type, and a second per-tenant configuration mechanism would split one rule across two places. A tenant that needs the rule runs on an engine that sets it.
- **The governance bench measures the governance step (R900.6).** `admit_records` needs a live blob store and mapping resolution, which would measure those rather than governance parsing. The bench calls `admit_record_governance`, the pure step `admit_record` runs first.
- **Access sync owns the read roles, not the markings (R902.2).** A snapshot carries principals and groups, so the update sets `source_access_public` and `source_access_read_roles`; groups appear as `group:<id>` and the read gate expands them. Markings come from governance and feed the replacement subject digest unchanged. `admit_access` and `admit_groups` are pure and return methods and per-item refusals; the `prepare` wiring is R902.3.
- **A new served method is its own chain (R001.1008).** `DataPrepDeclare` and `DataPrepDeclarationRead` need the method variants, scope, result contract, write classification, capability descriptor, canonical batch compile arm and generated client in one change, after `declare_data_prep` (R001.1007) exists.
- **Data-prep declarations are served from the graph pipeline, with an untyped payload (R001.1007 to R001.1009).** The declaration is a graph write that needs the request graph, row authority and placement fence, so it is routed beside `DocumentDelete` in `route_native_store_ops` and commits through `apply_one_change_envelope`; the stateless `source_ingest.rs` router has no graph. The wire payload is `serde_json::Value`, decoded by `validate_declaration`, so an unknown key or path-like value is refused with `DATA_PREP_DECLARATION_INVALID` instead of a generic decode failure. The replace is one digest-keyed write-set (node upsert, new field nodes and edges, removal of absent edges), so an equal write-set replays and a reader never sees a mixed set. The call answers `DataPrepDeclareReceipt{content_digest, written, unchanged}` until R001.1010 swaps in the shared `IngestBatchReport`. A request tenant that differs from the verified tenant is `INGEST_TENANT_MISMATCH`, the code R001.4 already uses.

- **A transcripts batch is an extension batch with typed items (R003.15, R003.16, R003.20).** Transcript items are typed threads and messages, not mapped records, so the batch takes the extension path and never resolves mappings. The rejected option ran the validator after `resolve_mappings`, which no extension batch calls. Item 0 is the one thread header and carries `dialect`; the dialect is a provenance label because the producer already parsed the lines. Concept refs are checked by one held-node read per distinct ref. Concept links need a new predicate, `:mentionsConcept`, because no existing predicate has a segment domain.
- **The near-duplicate index is durable bucket nodes (R702.3).** Each band of an original's signature names one `LshBucket` node in the batch graph, written in the batch envelope. The rejected option was an in-process cache rebuilt from stored signatures: it is a second copy of graph state that goes stale on another node and after a failed commit. The graph-version fence already serializes two batches that touch one bucket. A near duplicate is never indexed, so every link points at an original.
- **Row-version evidence is the record's raw blob (R901.2).** `admit_record` already stores the raw record as a content-addressed blob, so the evidence digest is that blob's digest. The record node carries the `SourceRowVersion` shape as its `row_version` property. The rejected options were a second artifact write and a separate evidence node, which would be a parallel route for the same bytes. Older versions stay readable through the change-envelope lineage.

## Decision: reconcile runs and plans are graph facts (R903.2)
The enumeration run and the plan are nodes written through the durable mutation path, never a side table. The run is the explicit machine `enumeration_run`; the extension carries the run metadata (`EnumerationPage`) because the earlier bare id list could not name a run, a page or completeness. The plan stores one due time per record so a record that stays missing keeps its first grace window and a record that reappears leaves the plan. The sweep commits through the internal mutation path and sends Document nodes through the `DocumentDelete` cascade planner, so the cascade rule exists once.
- **A container whose parent is unknown is refused (R904.2).** `upsert_containers` writes an edge only to a node that exists, and never drops the parent a container named. A parent outside the batch must already be held; a connector sends parents with or before their children. The edge is single-parent, so a move removes the old `containedIn` edge in the same call.
- **Atoms pack sentences, readers are feature-gated (R003.2, R700.1).** `decompose` takes the knob value as a parameter so the pure crate reads no registry; sentences pack greedily to the word limit. `medulla-modality` is a plain dependency of `medulla-document` (it was optional under `contract`) because `Fragment` carries `ModalityKind`; the reader parser crates stay behind empty `reader-<format>` features until their reader row passes the third-party policy test.
- **The batch report is the receipt's, with written counted as affected records (R606.1).** `SourceIngestionReceipt.report` counts `written` as records plus relationships affected, `refused` from governance, and `unchanged` as zero until `stamp_record` (R606.2) classifies by content hash; `classes` is empty until then.

## Ingest state machines (R911.1 to R911.4, R912.1)

- The two enrichment stages (`EnrichmentWorkStage`, `EnrichmentStage`) are a one-way ladder: classical, embedding, language model. One event `Escalated` climbs one rung; the last rung is terminal. `EnrichmentStage::after_abstention` builds a candidate stage from the initial stage by applying `Escalated` once per rung past the second, so a rung past the last stage is refused by the machine instead of by a `match`.
- `IngestStage` is the pipeline order fetch, extract, embed, index with events `Fetched`, `Extracted`, `Embedded`; `IngestStage::after_completed` replays them from the initial stage.
- `ThroughputState` starts `Unknown` and becomes `Complete` on `TelemetryFresh`; `TelemetryStale` returns it to `Unknown`. `measure_window` has no caller outside its tests, so it returns the typed refusal instead of hiding it.
- The enumeration run keeps one machine, now declared as `EnumerationRunMachine` with edges N01 to N03; `StagedRun::transition` is the only writer of `state`.
- **Readers cut into units derived from the byte knob (R700.2).** A source is cut at record boundaries into `ingest.reader_max_bytes / 1024` byte units, so one knob sets both the size limit and the unit size. Each unit is converted on its own thread, and a reader holds the source plus one copy of the text, which is the 2 times bound. Text-layer fragment spans address the source bytes; the HTML reader's spans address the extracted text. The reader row that needs a parser crate (PDF, Office Open XML, spreadsheet, email) adds its reader to the same registry.
- **A containers batch is planned once and compiled to methods (R904.3).** `plan_containers` in `source_hierarchy.rs` holds the rules (validation, cycle and depth check, unknown-parent refusal, dropped old edge); `upsert_containers` applies its plan to a graph core and `admit_containers` compiles the same plan into `AddNode`, `RemoveEdge` and `AddEdge` methods of the served batch, so there is one implementation. A record's container is named by its mapped `container_id` property and resolved under the record's own connector as the container source. The planner's refusals keep their codes; a code not yet on the wire is reported as the registered `SOURCE_CONTAINER_INVALID`. R904.3 is proved by the served container write and its receipt. The scoped search over a subtree is the proof of MEDULLA-FEDERATED-QUERY-R704.3, so R904.3 does not wait on that read.
