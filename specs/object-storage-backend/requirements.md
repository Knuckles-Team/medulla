# MEDULLA-OBJECT-STORAGE-BACKEND requirements

| ID | Requirement | Verification |
|---|---|---|
| `MEDULLA-OBJECT-STORAGE-BACKEND-R001` | **Typed object-store backend specification.** Model: a `StorageBackendSpec` declares the durable-store backend for a graph. Two variants exist. `local` is redb and is the default. `object_store` is S3-compatible. The spec names endpoint, bucket and root by secret reference only. It declares a durability class. It names a layout lineage entry by digest. Behavior: the engine opens the graph from the spec. An unbound spec refuses with a named reason before any effect. An unsupported spec refuses the same way. Caller chain: `Shard::open` (`crates/medulla-store/src/redb_store/shard.rs:226`) → `admit_backend_setting` (`shard.rs:1062`, reads the `MEDULLA_STORAGE_BACKEND` setting) → `StorageBackendSpec::admit` (`crates/medulla-storage/src/backend_spec.rs:117`) → `validate` (:79). Shape: `StorageBackendSpec`, `DurabilityClass`, `SecretRef` and `BackendSpecRefusal` live in `crates/medulla-storage/src/backend_spec.rs` and are re-exported from `crates/medulla-storage/src/lib.rs`. `validate` checks the layout digest against `ALL_LAYOUTS` and `pinned_layout_digest` of the owner-store lineage registry (`crates/medulla-storage/src/owner/lineage.rs`, MEDULLA-DURABLE-KERNEL-R003). Today `admit` returns `Unsupported` for `object_store`; R002 replaces that arm with the open path, and `server_startup.rs::open_persistence` (`crates/medulla-server/src/server_startup.rs:419`) selects `ObjectStoreBackend` once `admit` passes. The store-authority binding of MEDULLA-DURABLE-KERNEL-R021 is `crates/medulla-storage/src/physical/binding.rs` and stays the only binding. Refusal: the engine refuses a missing secret reference (`MissingSecretRef`), an unknown variant (`UnknownVariant`), a missing durability class (`MissingDurabilityClass`) and a layout absent from the lineage registry (`LayoutNotInLineage`). Every refusal is atomic and typed. Writes: none. Depends on: MEDULLA-DURABLE-KERNEL-R003, MEDULLA-DURABLE-KERNEL-R021. | Tests: `crates/medulla-storage/src/backend_spec.rs::tests::both_variants_round_trip_over_the_wire` (L1) and `crates/medulla-storage/src/backend_spec.rs::tests::refusals_are_typed_and_pure` (L1) round-trip both variants and assert each refusal leaves the spec unchanged. `crates/medulla-store/src/redb_store/shard.rs::backend_setting_tests::backend_setting_local_default_and_typed_refusals` (L1) covers the open-time admission. Served proof: `tests/test_object_storage_backend_spec.py::test_backend_spec_roundtrip_and_refusals` (planned) (L4). |
| `MEDULLA-OBJECT-STORAGE-BACKEND-R002` | **Object-store read path.** Stage: durable kernel, object storage read. Caller chain: `open_persistence` (`crates/medulla-server/src/server_startup.rs:419`) opening a graph whose `StorageBackendSpec` is `object_store` → new `ObjectStoreBackend::open` in `crates/medulla-persistence/src/object_store_backend.rs` (the backend wraps `RedbBackend`, `crates/medulla-persistence/src/redb_backend.rs:725`, so it lives at the persistence level) → `ObjectFetcher::materialize(version)` in new `crates/medulla-storage/src/object/fetch.rs`, declared in `crates/medulla-storage/src/object.rs`. The restore tool of `MEDULLA-ENGINE-PARITY-R016.2` calls the same function for an earlier version. Shape: the object access reuses the `object_store` crate trait that `crates/medulla-server-blob/src/blob/s3.rs` (`S3ChunkStore`) and `crates/medulla-persistence-ops/src/cold_tier_impl.rs` (`S3ColdTier`) already use; it adds no second S3 client. Layout under `<root>/<tenant>/<graph>/`: `HEAD` holds `{version, manifest}`; `manifests/<version:020>.json` is an immutable `VersionManifest { schema_version, tenant, graph, version, parent_version, snapshot, batches, digest }`; `segments/<sha256>.seg` holds content-addressed segments. A `SegmentRef` is `{ key, bytes, sha256 }` with 64 lowercase hex characters. A snapshot segment is the owner-table dump of `copy_declared_owner_tables` (`crates/medulla-storage/src/owner/registry.rs:499`, made reachable through one new `StorageKernel` method in `crates/medulla-storage/src/kernel.rs`). A `BatchSegment` is a MessagePack list of `MutationBatchRecord` (`crates/medulla-protocol-types/src/mutation_batch/model/records.rs:17`). Rule: `materialize(v)` reads manifest `v` and fetches its snapshot and batch segments. It verifies each SHA-256. It returns the verified segments; `ObjectStoreBackend::open` restores the snapshot into a local read-only store and replays the batches through the mutation kernel. A read never writes, copies or compacts the root. The local store is a cache that the root overrides. Refusals: `OBJECT_SEGMENT_MISSING` and `OBJECT_SEGMENT_DIGEST_MISMATCH`, each naming the version and key. Writes: none to the root. Depends on: `MEDULLA-OBJECT-STORAGE-BACKEND-R001`, `MEDULLA-DURABLE-KERNEL-R003`. | Test: `crates/medulla-storage/tests/object_reads.rs::versioned_reads_and_corruption_refusal` (planned) (L2) materializes three versions against the in-memory object store and corrupts one segment. It asserts the typed refusal and that earlier versions stay intact. Verified by the root slice test `tests/test_object_storage_reads.py::test_cold_open_from_root` (planned) (L4). |

| `MEDULLA-OBJECT-STORAGE-BACKEND-R003` | **Object-store commit path (commit before ack).** Stage: durable kernel, object storage commit. Caller chain: served `AddNode` → `commit_mutation_body` (`crates/medulla-server-mutation/src/mutation/commit_entry.rs:327`) → `commit_mutation_body_staged_path` (`crates/medulla-server-mutation/src/mutation/commit_paths.rs:151`) → `PersistenceBackend::commit_mutation_batch` (`crates/medulla-server-api/src/api/persistence.rs:275`; called at `commit_paths.rs:133`) → new `ObjectStoreBackend::commit_mutation_batch` in `crates/medulla-persistence/src/object_store_backend.rs`. The backend wraps the local `RedbBackend` as a cache. Rule: only the Raft leader of the graph's group publishes. Step 1: commit locally. Step 2: upload the `BatchSegment` of this commit as an immutable segment. Step 3: put `manifests/<v+1>.json` with create-only mode. Step 4: update `HEAD` with a conditional put on its current version tag. Step 5: ack the caller. Step 4 is the fence. The ack carries the existing receipt shape (`MutationBatchCommit`, `crates/medulla-protocol-types/src/mutation_batch/model/records.rs:31`). At open, a local store ahead of `HEAD` is discarded and rebuilt from the root. A local store behind `HEAD` replays the missing batches. Config: the spec's durability class decides when step 4 counts as durable; `ObjectStoreConditionalPut` means the store acknowledged the conditional put. Refusals: `OBJECT_PUBLISH_STALE` when step 4 loses the conditional put. The node then stops publishing, discards its local commit and re-fetches `HEAD`. `OBJECT_DURABILITY_UNDECLARED` at open for a spec without a class (the typed form of `BackendSpecRefusal::MissingDurabilityClass`). Evidence: a crash between steps 2 and 4 reopens at the prior version. The graph-copy row `MEDULLA-OBJECT-STORAGE-BACKEND-R003.2` consumes `RedbBackend::export_graph_raw_for_snapshot` (`crates/medulla-persistence/src/redb_backend/backend_shard_routes.rs:23`) and `import_graph_raw_from_snapshot` (:48). Writes: root objects only. Depends on: `MEDULLA-OBJECT-STORAGE-BACKEND-R002`, `MEDULLA-DURABLE-KERNEL-R016`. | Test: `crates/medulla-persistence/src/object_store_backend/tests.rs::commit_before_ack_and_partial_publish` (planned) (L3) interrupts between steps and reopens. It asserts the prior version is whole. It races two publishers and asserts one head. Verified by the root slice test `tests/test_object_storage_commits.py::test_ack_follows_head_update` (planned) (L4). |

| `MEDULLA-OBJECT-STORAGE-BACKEND-R003.2` | **Graph copy from the redb store to the object-store root with a verified digest.** Subsystem: object-store backend, operator command. Entry point: `medulla-server store-upgrade graph-copy <data-dir> <graph> --to <object-root> --confirm`. Caller chain: new `StoreUpgradeVerb::GraphCopy` in `src/operator_command.rs` (enum at :22, dispatched in `OperatorCommand::run` at :64) → new `crates/medulla-persistence-ops/src/store_upgrade/graph_copy.rs::copy_graph`, declared in `crates/medulla-persistence-ops/src/store_upgrade.rs` → a new paged export `RedbBackend::export_graph_raw_page` beside `export_graph_raw_for_snapshot` (`crates/medulla-persistence/src/redb_backend/backend_shard_routes.rs:23`, which returns the whole graph and so cannot hold the memory bound) → the object-store commit path of `MEDULLA-OBJECT-STORAGE-BACKEND-R003`. The command refuses while an engine holds the directory, as `MEDULLA-DURABLE-KERNEL-R070` does. Shape: `copy_graph` streams `RawGraphRows` (`crates/medulla-persistence/src/online_reshard.rs:234`) in batches of 1,000 rows. Each batch carries a row count and a SHA-256 digest. The destination writes under a staging prefix and publishes its manifest only after the whole-graph digest matches the source. Cost is O(nodes + edges) with memory under 128 MiB. Copies of different graphs run in parallel. Refusals: `GRAPH_COPY_DIGEST_MISMATCH` leaves the destination empty, and `GRAPH_COPY_DESTINATION_NOT_EMPTY` writes nothing. Depends on: `MEDULLA-OBJECT-STORAGE-BACKEND-R001`, `MEDULLA-OBJECT-STORAGE-BACKEND-R003`, `MEDULLA-DURABLE-KERNEL-R070`. | Test: `tests/test_graph_copy_served.py::test_digest_mismatch_leaves_destination_empty` (planned) (L4) copies a seeded graph, corrupts one batch, and asserts the refusal and an empty destination. A second case copies cleanly and reads the graph from the object root. Nightly benchmark `benches/graph_copy.rs` (planned) (L6): p50 under 400 ms and p99 under 1,500 ms per 100,000 elements. |
| `MEDULLA-OBJECT-STORAGE-BACKEND-R004` | **Shared-root multi-node access.** Stage: identity and placement, object storage open. Caller chain: node bootstrap `open_persistence` (`crates/medulla-server/src/server_startup.rs:419`) and the placement route handler `try_handle` (`crates/medulla-h-graph/src/placement.rs:367`) → `ObjectStoreBackend::open` (R002) → `ObjectFetcher::materialize(HEAD)`. Any node opens any tenant graph from the shared root. Branch and commit coordination keep their owners: Raft for commits (R003) and the placement authority for routes. The store layer adds no second consensus. Shape: no new file; `ObjectStoreBackend::open` (R002) reads the config key and passes it to `ObjectFetcher::materialize` (`crates/medulla-storage/src/object/fetch.rs`) as its fetch fan-out, and checks the placement route before the first fetch with the route lookup of `crates/medulla-h-graph/src/placement.rs`. Rule: a node without a local copy fetches the `HEAD` manifest, its snapshot and batch segments in one bounded pass. It never replays history before the manifest snapshot. Config: server config key `object_store.open_parallel_fetches`, default 8, bounds [1, 64], unit requests. A node that lost its local state reopens from the root with no data loss. A local cache whose version trails `HEAD` replays the missing batches before serving. Refusals: `PLACEMENT_NOT_GRANTED` when the node holds no placement route for the tenant, before any read (consumer row `MEDULLA-PLACEMENT-R611.7`). Writes: none to the root. Depends on: `MEDULLA-OBJECT-STORAGE-BACKEND-R003`, `MEDULLA-PLACEMENT-R611`. | Test: `crates/medulla-persistence/src/object_store_backend/tests.rs::two_nodes_read_identical_state` (planned) (L3). Verified by the root slice test `tests/test_object_storage_shared_root.py::test_multi_node_cold_open_and_rejoin` (planned) (L4). It opens one root on two engines and drops one node's local state. It asserts identical served state after rejoin. |
| `MEDULLA-OBJECT-STORAGE-BACKEND-R005` | **Comparative cost gate across releases.** Stage: release qualification (nightly). Caller chain: the nightly suite job → new `benches/object_store_cost.rs` (a `[[bench]]` entry in the root `Cargo.toml`, as at :1976 for `write_coalescer_bench`) → new `scripts/object_store_cost_gate.py`. Shape: a new `CountingObjectStore` wrapper over the `object_store` trait in `crates/medulla-storage/src/object/counting.rs`. Rule: the harness drives one cold lifecycle against the current build and the previous release tag. The lifecycle is open, read 1,000 nodes, commit 100 batches and merge two branches (`MEDULLA-BRANCH-MERGE-R003`). It records four dimensions: time, object actions, bytes and peak memory. Action and byte counts come from the counting run. Time and memory come from a separate matched run without the wrapper. Output is JSON lines with `schema_version`, `host`, `revision`, `lifecycle_digest`, `dimension`, `value`. Actions are counted per shard, which a single-store harness cannot express. The gate fails the release when object actions at open grow more than 10 percent. It compares with the previous release record in `benches/baselines/object_store_cost.json` (new). Refusals: `COST_RUN_UNSTAMPED` and `COST_RUN_UNPINNED` mark the run claim-ineligible; it never enters the evidence. Writes: the records file. Depends on: `MEDULLA-OBJECT-STORAGE-BACKEND-R003`, `MEDULLA-BRANCH-MERGE-R003`, `MEDULLA-DURABLE-KERNEL-R042`. Budget runs in the nightly suite (MEDULLA-DECISION-ENGINE-R178.1), never in a PR. | Test: `tests/test_comparative_cost_gate.py::test_regression_guard_and_claim_eligibility` (planned) (L4) injects a 15 percent growth of open actions and asserts the gate fails. It asserts an unstamped run is claim-ineligible. |
