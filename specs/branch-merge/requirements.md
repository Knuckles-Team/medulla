| `MEDULLA-BRANCH-MERGE-R002` | **Branch-scoped mutations on one commit chain.** Subsystem: ingest, branches. Entry: new `Method::BranchWrite { tenant, graph, branch, mutation }` (`crates/medulla-protocol-types/src/protocol/method/method_11.rs`), where `mutation` is one boxed graph mutation. Caller chain: `dispatch_graph_lifecycle_methods` (`crates/medulla-server-router/src/dispatch/router/graph_lifecycle.rs`) → `handle_branch_write` (`crates/medulla-server-router/src/dispatch/router/branch_write.rs`) → `resolve_target` (`crates/medulla-h-graph/src/graph_ops/branch.rs`), which maps `(tenant, graph, branch)` to the branch target graph before the mutation compiles → `dispatch_graph_op` on that target graph, which commits through the ordinary commit and raft path → `BranchRegistry::append_commit` (`crates/medulla-persistence/src/branch_registry_store.rs`). Shape: the target graph is `branch_target_graph(BranchRef)` (`crates/medulla-types/src/branch.rs`), a pure function of the branch identity, so the branch holds its own writes and `main` (the base graph itself) and sibling branches never see them until merge. The first write creates the target graph. Each write appends a `BranchCommit { id, branch, parents, engine_version, manifest_digest, actor, created_at_ms }` with the prior head as its single parent; the commit row, the batch-to-commit index row and the head advance (`Branch.head_commit`) are written in ONE registry transaction. This is the single commit chain. A source changeset (MEDULLA-SCM-R002) is the payload of the branch commit that carries it. No second chain exists. `manifest_digest` is the SHA-256 of the mutation's canonical named MessagePack and `engine_version` is the target graph version after the mutation. The idempotency key is `(tenant, graph, branch, principal, idempotency_key)`, derived by `branch_batch_id` (`crates/medulla-server-api/src/batch_compile/digest.rs`), the `lifecycle_batch_id` family extended with the branch name. A replay finds the batch index row and returns the original commit without a second graph change. The receipt `BranchWriteReceipt { branch_head, commit, target_graph, replayed }` (`crates/medulla-types/src/branch.rs`) carries `branch_head`. The `mutation` must be a graph mutation the verified context may run; a read, a lifecycle operation or another branch operation refuses `BRANCH_WRITE_INVALID`. Refusals: `BRANCH_UNKNOWN` (also for the trunk name `main`, which is the base graph and takes a plain write), `BRANCH_DELETED`, `BRANCH_TENANT_DENIED`, all before any graph change. Writes: commit-before-ack; the graph change goes through the existing commit and raft path, then the registry commit. The branch commit is the sole writer of the branch head. Depends on: MEDULLA-BRANCH-MERGE-R001, MEDULLA-DURABLE-KERNEL-R009, MEDULLA-DURABLE-KERNEL-R019. Child: MEDULLA-BRANCH-MERGE-R002.1 (typed slice). | Test: `tests/test_branch_scoped_mutation.py::test_branch_write_invisible_until_merge` (L4). It writes on a branch and asserts `main` is unchanged. It asserts the replayed receipt is identical. |
| `MEDULLA-BRANCH-MERGE-R003` | **Merge base and fast-forward.** Subsystem: ingest, branches. Entry: new `Method::BranchMerge { tenant, graph, source, target, merge_base }`, added beside `CreateBranch` in `method_11.rs`. Caller chain: the same `dispatch_graph_lifecycle_methods` arm group (`graph_lifecycle.rs:7`) → new `handle_branch_merge` in `crates/medulla-h-graph/src/graph_ops/branch.rs` → `merge_base` and `classify` in `crates/medulla-types/src/branch.rs`. Shape: enum `MergeOutcome { UpToDate, FastForward, Merged, Conflict }` serialized as `up_to_date`, `fast_forward`, `merged`, `conflict`. Merge base is the lowest common ancestor on the commit DAG chosen by highest generation number; `BranchCommit` stores its generation. A tie goes to the lexicographically smallest commit id. `up_to_date`: the source head is an ancestor of the target head. `fast_forward`: the target head is an ancestor of the source head. The handler moves the target to the source head without an entity scan. The receipt names the source head as merged parent. Refusal: `BRANCH_NO_COMMON_ANCESTOR`, typed, never an implicit base. Writes: `fast_forward` writes one pointer move through the commit path. `up_to_date` writes nothing. Depends on: MEDULLA-BRANCH-MERGE-R002. | Test: `tests/test_branch_merge_base.py::test_merge_outcomes_up_to_date_and_fast_forward` (planned) (L4). It drives four topologies: linear, diamond, disjoint and equal heads. It asserts the closed outcome set and the diamond merge base. |

| `MEDULLA-BRANCH-MERGE-R005` | **Epistemic conflict resolution.** Subsystem: ingest, branches. Caller chain: `merge_entities` (R004) → new `resolve` in `crates/medulla-h-graph/src/graph_ops/branch/conflict.rs` → `merge_conflicts` in `crates/medulla-h-graph/src/graph_ops/branch.rs`, the placement fixed by MEDULLA-DECISION-ENGINE-R828 → `Decide` with `QuestionKind::ResolveConflict` (`crates/medulla-h-decide/src/decide/family/resolve_conflict.rs`, MEDULLA-DECISION-ENGINE-R828).
